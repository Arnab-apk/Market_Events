# Shared implementation contract

Read `docs/archive/planning/MVP_IMPLEMENTATION_GUIDE.md`. The guide initially ended at section 7.4 and was extended concurrently through section 18 during this build. Its requirements take precedence; this contract records shared implementation interfaces and frozen numerical choices. All bundled data fixtures are explicitly synthetic. Actual local inference is tested separately and is never presented as real-market validation.

Root owns schemas.py, config.py, model_client.py, agents/, pipeline.py, __main__.py, pyproject.toml and integration. Data agent owns ingestion.py, event_memory.py, storage.py and related tests. Quant agent owns exposure.py, market_features.py, fusion.py, outcomes.py, configs/, tests/fixtures/ and related tests. UI agent owns app.py, .streamlit/, README.md and docs/ (except this contract), experiments.py and UI/experiment tests. Do not edit others' files. Coordinate via reading shared files; no nested agents. Use Python 3.10+, Pydantic v2. Plain functions. No git commits.

## Schemas (root creates immediately)

All extend Pydantic BaseModel with extra=forbid. Dates must be aware, normalized UTC. JSON serializers supported. IDs str. `Article`: article_id, source_url, text, published_at, first_seen_at (required), source_version='1', content_hash (computed SHA256 whitespace-normalized text), predecessor_id=None. `MarketObservation`: observation_id computed from instrument_id,timestamp,contract_id; instrument_id, market_family Literal[equity,commodity,benchmark], timestamp, available_at (required), open/high/low/close float>0, volume float>=0, currency, unit, contract_id=None. `ImportResult`: records list[Any], errors list[dict], warnings list[str].

`ExecutionPolicy` str enum llm_only, slm_filter, slm_delegate. `FilterDecision`: relevance Literal[relevant,irrelevant,uncertain], event_type Literal[earnings,order_announcement,commodity_supply_disruption,other,uncertain], candidate_entities list[str], source_spans list[str], reason str, trace_id str|None.

`EventExtraction`: event_id str, source_version str='1', event_type as above, company_id str|None, candidate_entities list[str]=[], commodity_id str|None, direction Literal[positive,negative,neutral,uncertain]='uncertain', amounts list[dict]=[], source_spans list[str], validation_status Literal[validated,unresolved,unsupported]='unresolved', reason str='', trace_id str|None. Extraction only accepted when spans occur in article. Model direction is narrative context; never a price or return.

`ExposureRule`: company_id, commodity_id, relationship, source, direction int restricted +/-1, effective_at datetime, known_at datetime, version str, rule_id str. `ExposureMatch`: status Literal[matched,missing,ambiguous,not_required], rule ExposureRule|None=None, reason=''.

`MarketFeatures`: decision_time datetime, company_id str|None=None, values dict[str,float|None], observation_ids list[str], missing list[str], stale list[str], definition_version='features-v1'. Standard keys equity_return, benchmark_return, excess_return, relative_volume, commodity_return. Returns fractional; relative volume latest volume / preceding 5 session mean; price returns latest / previous -1. Staleness >4 calendar days at EOD. Guard availability <= cutoff AND timestamp <= cutoff. Never combine different commodity contracts.

`Assessment`: direction Literal[positive,negative,neutral,abstain], evidence_score float|None, coverage float 0..1, conflicts list[str], abstention_reasons list[str], inputs dict[str,Any], rules_version str, explanation str. Frozen baseline directional features: equity excess return clipped to [-1,1] using 0.02 scaling; commodity return times reviewed exposure sign clipped using 0.03 scaling. Earnings/order: equity required; disruption: equity and commodity required plus mapping. Relative volume context only. Baseline equity 0.6 commodity 0.4; equity-only optional ablation; threshold +/-0.15; minimum coverage 0.6. Missing mandatory evidence gates direction regardless score.

`ModelCall`: trace_id, run_id, task, provider, model, prompt_version, input_tokens/output_tokens int|None, latency_ms float, retries int=0, status str, error str|None, mode Literal[live,replay], request_hash str|None. `AnalysisRun`: run_id, article_id, event_id str|None=None, policy ExecutionPolicy, decision_time datetime, status str, created_at datetime, config_snapshot dict, memory dict={}, filter_decision FilterDecision|None, extraction EventExtraction|None, exposure ExposureMatch|None, features MarketFeatures|None, assessment Assessment|None, calls list[ModelCall], error str|None, latency_ms float=0, mode live/replay. `EventOutcome`: run_id, status Literal[pending,completed,invalid], entry_time/exit_time datetime|None, entry_price/exit_price float|None, gross_return/net_return/benchmark_return/excess_return float|None, label str|None, reason str, definition_version='outcome-v1'.

## Public interfaces

* ingestion.import_articles(path: Path)->ImportResult; import_market_prices(path: Path)->ImportResult. Parse each row independently; readable line errors.
* Storage(path: Path): initialize schema on init; close(), context manager; add_articles(records)->int; add_observations(records)->int; get_article(id)->Article|None; list_articles()->list[Article]; list_observations()->list[MarketObservation]; list_events()->list[EventExtraction]; save_run(run)->None (transaction events/event_sources, runs/calls/assessment); get_run(id)->AnalysisRun|None; list_runs()->list[AnalysisRun]; save_outcome(outcome), get_outcome(run_id); list_outcomes()->list[EventOutcome]. Persist JSON plus indexed keys as needed; FK each connection; uniqueness; never replace saved runs.
* event_memory.classify_article(article, articles:list[Article], decision_time:datetime)->dict with status new/duplicate/update/unresolved, related_article_ids list and reason. Only predecessors published AND first_seen <= cutoff; exclude self; exact content duplicate first. New means within dataset. Explicit predecessor handles update.
* exposure.resolve_company(candidates:list[str], companies:list[dict])->str|None; find_exposure(event, rules:list[ExposureRule], decision_time)->ExposureMatch. companies config JSON list {instrument_id,name,aliases:list,sector,benchmark_id}; 5 stocks 2 sectors. Config source conceptual reviewed assumptions explicitly flagged.
* market_features.compute_market_features(observations,decision_time,company_id=None,commodity_id=None,benchmark_id=None)->MarketFeatures.
* fusion.assess_evidence(event, exposure, features, rules:dict, include_commodity=True)->Assessment. Config fusion_rules.json dict, version required.
* outcomes.evaluate_outcome(run,later_observations,benchmark_id=None,cost_bps=10.0)->EventOutcome. Entry first equity session with timestamp > cutoff, at open; exit fifth trading session INCLUDING entry, at close. Only finished/available observations as of supplied evaluation_time optional (default now UTC); leave pending if horizon incomplete. Benchmark entry/exit exact matching session dates, missing benchmark stays explicit. Net = gross - cost_bps/10000 round trip. No entry/exit inference from calendar days.
* config.Settings: root Path, database_path Path, mode='replay', slm/llm ModelSettings, max_requests=4, max_tokens=12000, timeout_seconds=60; load_settings(root=Path('.'))->Settings; configuration files read relative root. All config snapshots omit credentials.
* pipeline.Dependencies(storage,settings,client=None) owns actual clients/configs; analyse_article(article_id,decision_time,policy,dependencies)->AnalysisRun (always persisted after lookup); run_demo(root=Path('.'),database_path=None)->list[AnalysisRun] imports fixtures and runs 3 representative articles at 2026-01-12T12:00:00Z replay; compute_outcomes(dependencies)->list[EventOutcome]. Optional explain_run(run_id,dependencies)->str.
* CLI python -m market_events demo [--database PATH]; import-articles PATH; import-market PATH; analyse ARTICLE_ID --decision-time ISO --policy ... [--mode replay/live]; outcomes; export --output PATH; experiments [--output PATH]. Default db data/market_events.sqlite. Global --database, --root supported BEFORE subcommand. UI sets Dependencies and calls public workflows. Replay only fixture outputs; unknown article errors visibly, NEVER simulated live success.
* UI sidebar local paths, labelled mode, import upload, manual article, research workbench with article selection/aware IST cutoff, analyse, saved-run evidence/source/fusion/trace/outcomes and JSON export. Demo load explicit button (no writes on page open). Experiments uses saved calls/runs grouped policy and ablation; no synthetic claims of measured model quality.

## Technical indicators and live data extension (2026-10-24)

The user requested coordination with the Understanding Herdr tab, technical indicators and a real-data workflow configured through local credentials, together with a clearer dashboard. Ownership for this extension:

- Understanding: schemas, config, pipeline, market_features, CLI, backend integration tests, new `docs/LIVE_SETUP.md` and `docs/archive/planning/PROTOTYPE_WORKFLOW_AND_FEATURES.md`.
- Quant: new `technicals.py` and `test_technicals.py`.
- Data: new `live_data.py`, `test_live_data.py` and `configs/live_universe.json`.
- UI & Docs: app, Streamlit theme, AppTest coverage and existing UI documentation. Coordinator owns this contract and final integration verification.

`compute_technicals(observations, decision_time, company_id) -> TechnicalSnapshot` is pure local computation. Snapshot fields are decision_time, company_id, values, missing, stale, observation_ids, history_bars, required_history, interpretation and definition_version. `AnalysisRun.technicals` stores the optional snapshot; indicators do not change the existing numerical event score. Cutoffs require both observation timestamp and availability; insufficient or ambiguous history stays explicit. Quant documents keys, seeding and warm-up conventions in its module.

`Settings.universe` selects `demo` or `live`. Live instrument IDs use `LIVE:NSE:<symbol>`; benchmark is `LIVE:NSE:NIFTY50`. Synthetic configurations and reviewed exposure assumptions must not silently become live mappings. `configs/live_universe.json` is an object with version, source and instruments (five equities plus benchmark). `get_live_universe(settings_or_root) -> list[dict]` reads metadata without network calls. Instrument records include instrument_id, name, provider_instrument_key, exchange, currency, unit and source; provider keys are resolved against the provider master, never guessed.

`Settings.live_data` contains provider='upstox', access_token (SecretStr excluded from snapshots), timeout_seconds=20, min_request_interval_seconds=0.25, max_requests=30 and news_max_pages=3. Environment lookup prefers `UPSTOX_ANALYTICS_TOKEN`, then `UPSTOX_ACCESS_TOKEN`. Tokens remain local; the UI reports configuration presence without claiming a verified connection.

`sync_live(dependencies, company_ids, lookback_days=550, include_news=True, now=None) -> dict` runs only after explicit submission. The JSON report includes provider, fetched_at, requested_company_ids, observations_added, articles_added, errors [{company_id, stage, message}], warnings, data_source, network_requests, universe metadata, article_ids and decision_time. The applicable benchmark is fetched alongside selected equities. Daily candle start times become completed NSE session close times; unfinished sessions are skipped. Availability and first_seen reflect actual fetching. Identical refreshes retain the first recorded availability; revisions cannot overwrite immutable observations. Never use newly downloaded history at a cutoff earlier than its recorded availability.

The technical dashboard works on imported price history without news or model credentials. Refreshing data and invoking models are separate explicit actions; viewing pages, reading metadata and changing filters never trigger either. Provider adapters are verified with mocked responses by default. Live provider success requires an actual configured, successful request and must never be inferred from token presence or replay.

Coordinator integration additions: `exporting.py` resolves the union of saved market-feature and technical-snapshot observation references, preserving missing IDs and technical context in JSON/Markdown exports. `Storage.save_run` compares interpreted optional defaults for legacy snapshots without rewriting saved JSON; actual changes remain immutable conflicts. The coordinator owns these two modules and their tests for this extension.
