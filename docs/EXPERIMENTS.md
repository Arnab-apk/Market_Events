# Experiments and interpretation

This delivery supplies a comparison mechanism, not a validated research result. Bundled articles, prices and recorded outputs are synthetic. There is no held-out real-world corpus, established predictive quality, or measured live model advantage.

The local synthetic development pilot completed 30 `qwen3.5:2b` filtering requests with zero failures and 24/24 expected items forwarded. Three of three tested `gemma4:e4b` extractions were source-grounded after the typed-amount schema fix. This exercises actual inference on synthetic inputs; it is not a held-out benchmark or evidence of live-market validation. Preserve individual call records and their prompt/model/configuration versions when interpreting these counts.

`summarize_policies` groups analysis runs by execution policy AND replay/live. Optional explanation children are excluded from analysis counts, cohorts and ablations; their resources appear separately in `explanation_summary`. Explicit repeated analyses still contribute repeatedly. Summaries report calls, failures, token totals, latency, assessed runs and abstentions. If any call lacks either token count, or its mode disagrees with the containing run, group token totals stay null and usage completeness is false; mode mismatches are counted explicitly. No calls also means unavailable usage, not zero measured consumption. Replay latency is not model latency. This is a descriptive audit, not an independent sample.

`matched_policy_inputs` reveals common article/cutoff/mode cohorts and whether all three policies exist, including failed runs. It lists statuses and configuration variants. Fingerprints compare saved snapshots except local root/database paths; an empty snapshot is not a confirmed match. Matching those fields alone does not guarantee a controlled experiment: compare source hashes, data versions, exposure/fusion rules, prompt versions, actual model IDs and provider settings as well. The exported run manifest links mode, policy, cutoff, status, parent and configuration fingerprint to each run. Outcomes retain their run's mode/policy/article/cutoff. Do not infer quality from aggregate call reduction.

`compare_ablations` recomputes equity-only and commodity-inclusive fusion using the same saved extraction, exposure and features. It takes rules from the run snapshot, or the assessment's saved exact rules; an explicit caller-supplied fallback is labelled separately. Missing/invalid snapshots or inputs and unresolved source history yield unavailable results. Each computed row retains the saved status/direction for comparison. These calculations never rewrite original runs or outcomes and never trigger new inference. For earnings/orders without a commodity path the two variants may agree by design.

Existing local artifacts were inspected read-only during this continuation; no new inference or provider results were produced. `runs/local_smoke.json` records three filter requests and one validated extraction out of three; `runs/local_model_pilot.json` records the later 30-filter/three-extraction pilot described above. Both identify authored synthetic inputs and mixed cold/warm calls. Neither is a held-out study.

The existing `runs/handover.json` contains seven synthetic articles, 24 runs (21 live and three replay) and 14 outcomes (12 completed, two invalid). `runs/handover.usage.json` contains 32 call records. The archived `runs/policy_comparison.json` reports live call counts of 8 for `llm_only` and 9 each for `slm_filter` and `slm_delegate`; it provides no evidence of call savings for these inputs. Its three policies differ on `syn-005` (irrelevant versus abstained). Those artifacts predate this continuation's observation export, explanation separation and configuration-cohort fields; regenerate exports from saved storage to obtain the new fields, without rerunning inference. Local `runs/` artifacts are ignored and may be absent from a fresh checkout.

Outcomes are exported separately with pending/invalid/completed status. They are not classification ground truth. A credible next study needs permitted real inputs, a dated corpus manifest and reviewed labels, temporal train/pilot/test separation, fixed outcome costs and coverage rules, paired configurations, error categories, and actual live token/timing measurements. Report negative results and missing cases. No accuracy, F1, calibration or profitability is fabricated here.
