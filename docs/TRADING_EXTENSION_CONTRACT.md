## Quant public API (frozen for UI)

`prepare_history(observations, instrument_id, start_date, end_date, as_of=None) -> list[MarketObservation]`: retrospective OHLC research, timestamps within inclusive session dates, availability <= aware as_of (default now UTC), end <= 2020-12-31. Reject conflicting same-session records, units/currency/contracts changes. Sort and collapse exact duplicates. Do not backdate availability or claim historical point-in-time knowledge. Explicit error on no eligible bars. Preserve pre-start warmup by UI passing a suitably earlier start when necessary or document selection window convention.

`indicator_series(bars) -> dict[str, list[dict]]`: chart-ready `{time: 'YYYY-MM-DD', value: float}` for keys sma20, sma50, sma200, ema20, ema50, rsi14, macd_line, macd_signal, macd_histogram, bollinger20_middle/upper/lower, atr14, adx14. Missing warmups absent, not zero. Deterministic causal formulas consistent with technicals.py.

`run_backtest(bars, strategy='sma_cross', initial_capital=100000.0, cost_bps=10.0, slippage_bps=5.0, fast_period=20, slow_period=50, rsi_buy=30.0, rsi_sell=70.0) -> dict`: strategies buy_hold, sma_cross, ema_cross, rsi_reversion, macd_cross, bollinger_reversion; long/cash, close signal -> NEXT session open execution; final mark-to-market and explicit open-position status; costs charged each fill; deterministic no future leakage. Return JSON-safe keys strategy, assumptions (list[str]), equity (list[{time,value,benchmark}]), trades (list[dict]), daily_returns (list[float]), metrics (dict including total_return, benchmark_return, max_drawdown, sharpe, cagr, closed_trades, win_rate). Validate finite inputs/costs, minimum bars, positive equity. Warn on unadjusted OHLC/gaps/survivorship; benchmark same costs convention documented. Do not call models/network/storage.

`monte_carlo(daily_returns, initial_capital=100000.0, simulations=300, horizon=252, seed=42, block_size=5) -> dict`: seeded moving-block bootstrap, bounded counts/horizon, no global RNG mutation, reject NaN/inf/returns <= -1/insufficient returns. Return paths (list[list[float]], include initial capital), bands (list[{step,p05,p50,p95}]), metrics (dict with probability_loss, p05_terminal, median_terminal, p95_terminal), assumptions list[str]. This models resampled historical returns, not probability of future market outcomes.

## Quant implementation interface notes (append-only)

- `prepare_history` takes Python `date` bounds (not datetime/string) and an optional timezone-aware datetime cutoff. Session dates are Asia/Kolkata, inclusive. Matching equity rows must satisfy both timestamp and available_at <= cutoff. It sorts and revalidates records, collapses exact full-record duplicates, rejects any other selected same-session conflict and currency/unit/contract changes, and raises `ValueError` on an empty selection. Availability timestamps are preserved. The caller must explicitly select an earlier start to include warmup; indicators/backtests operate on exactly the supplied bars with no hidden prehistory. All three bar APIs enforce the 2020-12-31 session-date ceiling, even when called directly. Indicator/backtest APIs do not filter by current availability: call `prepare_history` first to apply an as_of selection. Bars represent retrospective research, not a reconstruction of historical availability.
- `indicator_series` returns all fourteen frozen keys, each containing only `{time: str, value: float}` points after its seed. Empty input returns empty lists. SMA200 first appears on bar 200, EMA50 on bar 50; all other seeds match technicals-v1. No chart point is emitted for a missing warmup. Time strings use NSE session dates. Input is sorted, exact duplicates collapse, mixed instruments/non-equity/ambiguous sessions fail.
- Backtest minimum counts include one execution session: buy_hold=2, SMA/EMA=slow_period+1, RSI=16, MACD=35, Bollinger=21. Fast/slow are integer periods with 1 <= fast < slow <= 10000. MA/MACD strategies enter on the first fully seeded bullish relationship, thereafter hold long above and cash below; equality retains the current holding. RSI enters at/below rsi_buy and exits at/above rsi_sell; 0 <= buy < sell <= 100. Bollinger enters strictly below the lower band and exits at/above the middle band. A signal at the final close cannot fill. Warmup capital remains cash and is included in metrics.
- Buy price is next open * (1 + slippage_bps/10000); sell price is next open * (1 - slippage_bps/10000). Fees are cost_bps/10000 times slipped notional on each fill. Both bps values must be finite in [0,10000), capital finite and positive. Fractional buy quantity is cash / (buy_price * (1 + fee_rate)); sells return quantity * sell_price * (1 - fee_rate). No leverage, rounding to lots, dividends, cash interest or taxes. The benchmark signals at the first close and buys at the second bar open with the same buy sizing/fees/slippage, then stays long. Neither series charges a hypothetical terminal exit.
- `equity` has one `{time,value,benchmark}` record per selected bar, with both first-bar values equal to initial_capital. `daily_returns` has len(equity)-1 consecutive arithmetic equity returns, including cash/warmup and execution costs. `trades` is a fill ledger, each row `{time,signal_time,side,quantity,price,reference_price,notional,fee,slippage_cost,cash_after,realized_pnl,trade_return}`. Side is `buy`/`sell`; reference_price is raw open; realized_pnl/trade_return are null for buys and include both entry/exit costs for sells. slippage_cost is quantity * abs(fill_price - raw_open). There is no artificial final sell.
- The additional top-level `open_position` is null when flat, otherwise `{entry_time,entry_price,entry_fee,cost_basis,quantity,mark_price,market_value,unrealized_pnl}` at the final close; cost_basis includes entry fee. Metrics contain the frozen keys plus `final_equity`, `total_fees`, `total_slippage` (strategy fills only). Return/drawdown/win-rate metrics are fractions; max_drawdown is nonpositive. Closed trades count sells; a win has realized_pnl > 0. win_rate is null without closed trades. Sharpe is sqrt(252)*mean/sample_stdev of daily_returns with zero risk-free rate, null when fewer than two returns or zero deviation. CAGR uses actual elapsed session dates / 365.25. Nonfinite arithmetic or nonpositive wealth raises ValueError; JSON contains no NaN/Infinity.
- Monte Carlo accepts >=2 finite arithmetic returns strictly greater than -1, 1 <= block_size <= number of returns, integer simulations 1..2000, integer horizon 1..2520, simulations*(horizon+1) <= 2,000,000, and an integer seed 0..2**64-1; bools are rejected as numeric parameters. A local NumPy PCG64 generator samples uniformly from overlapping, non-circular historical blocks with replacement, concatenates and truncates them at horizon. Each path has horizon+1 positive finite wealth values including initial capital. Bands have horizon+1 rows and linear empirical p05/p50/p95 quantiles across paths, including step zero. probability_loss is the fraction of terminal values strictly below initial capital; terminal metrics match the last band. Input portfolio costs are already embedded in returns; no additional friction is imposed. Scenario frequencies do not estimate probabilities of future outcomes.

## Data public API notes (implemented 2026-10-26)

`sync_historical(dependencies, company_ids, start_date=date(2015, 1, 1), end_date=date(2020, 12, 31), now=None) -> dict` is ready for an explicit download form submission. Importing the module or reading universe metadata does not fetch data. No news/model calls or synthetic fallbacks. `sync_live` retains its existing behavior.

Inputs: a list/tuple of current local live equity IDs (deduplicated); configured benchmarks are included once. Dates must be Python `date` objects, with `2000-01-01 <= start_date <= end_date <= 2020-12-31`, ending before the current IST date. Invalid dates, empty/invalid-only selections and missing configuration return explicit `errors` without network calls. Mixed valid/unknown IDs report validation errors for unknown IDs while processing valid selections. An optional naive `now` raises `ValueError`; an aware `now` is an offline-test clock injection. Production callers should omit it.

Official limits verified on 2026-10-26: [Historical Candle Data V3](https://upstox.com/developer/api-documentation/v3/get-historical-candle-data/) documents `days/1`, daily availability from January 2000, an inclusive end date, and a maximum one-decade retrieval window. The implementation uses adjacent inclusive chunks ending at December 31 of the ninth following year (or the requested end, whichever is earlier), each within ten calendar years; the default 2015-2020 window needs one candle request per instrument. [Upstox rate limits](https://upstox.com/developer/api-documentation/rate-limiting/) list historical candles under standard APIs: 50 requests/second, 500/minute, 2000/30 minutes, per API/user. This function reuses `settings.live_data` request budgets, pacing, timeout and response-size limits, counts the master download against the budget, and performs no retries. HTTP 401/403/429 stop subsequent provider requests; other failed chunks remain explicit while later chunks can proceed. Local limits do not account for concurrent sessions or other clients sharing an account.

Report keys preserve the live adapter conventions: `provider`, `fetched_at`, `decision_time`, `requested_company_ids`, `observations_added`, `articles_added` (always 0), `article_ids` (always empty), `errors` (list of `{company_id, stage, message}`), `warnings`, `data_source`, `network_requests`, `universe`; `universe_version`/`universe_source` appear after valid local configuration is read. Added fields:

- `requested_start`, `requested_end`: inclusive ISO dates (null for a malformed non-date input).
- `actual_start`, `actual_end`: aggregate ISO session-date extrema across bars accepted by this invocation, or null when none were accepted. These are the union's extrema, not common coverage across every instrument.
- `coverage`: instrument-ID-keyed dictionary for selected equities and their benchmarks, initialized before authentication/download. Each value is `{actual_start: str|null, actual_end: str|null, bars: int, chunks_planned: int, chunks_requested: int, chunks_completed: int}`. `bars` counts unique accepted session dates including identical stored observations returned again, excluding rejected revisions. `chunks_requested` counts actual candle HTTP attempts; `chunks_completed` counts successful structurally valid candle responses, including empty responses. Check `errors` as well as coverage: a completed chunk can still have empty/malformed/conflicting rows. Validation failures can leave coverage empty.

Coverage describes this download, not preexisting cached observations. Empty or entirely unusable chunks have explicit errors; partial results are retained. All accepted session dates fall within both the requested interval and their request chunk. Aware provider timestamps are converted to IST session dates and stored at 15:30 IST (10:00 UTC). Each new observation's availability is its actual response receipt time, never its historical session date. Identical observations preserve first saved availability across downloads; revisions retain the immutable saved version and report a conflict. `fetched_at`/`decision_time` are completion timestamps on completed attempts, using the injected clock only in tests.

Limitations for UI/research: extrema do not certify gap-free trading sessions or true listing dates; there is no historical exchange calendar, adjustment verification, delisted-instrument discovery or point-in-time constituent reconstruction. Current instrument-master mappings are not proof that historical data exists. No real provider/account data was downloaded during implementation; offline tests use synthetic records and a fictional token.
