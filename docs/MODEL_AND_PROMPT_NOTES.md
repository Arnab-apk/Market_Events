# Model and prompt notes

Three policies are exposed by their contract identifiers: `llm_only`, `slm_filter`, `slm_delegate`. The SLM handles relevance and permitted low-level structured tasks; relevant complex or uncertain items escalate to the LLM. Numerical features, mapping eligibility, fusion and outcome returns belong to ordinary code. Narrative direction cannot supply a price return.

Actual model identifiers, provider, prompt version, usage, retries and latency must be read from each saved call and configuration, not inferred from a policy label. Inspect `model_client.py`, `agents/` and `prompts/` for routing and request details. Functional pilot results below do not establish model quality or latency superiority.

The synthetic development pilot used local `qwen3.5:2b` for SLM filtering and `gemma4:e4b` for LLM extraction. Across 30 filtering requests there were zero failures and all 24 expected items were forwarded. After the typed `ExtractedAmount` schema fix, three of three tested Gemma extractions were grounded in their supplied sources. Earlier extraction failures exposed an untyped amount key; that failure and its correction are development evidence, not a held-out evaluation. These small synthetic results do not establish real-data validity, predictive performance or comparative model quality.

These counts come from the pre-existing `runs/local_model_pilot.json` metadata, not a provider run during this continuation. `runs/local_smoke.json` retains the earlier one-of-three validated extraction result. The archived policy comparison also contains negative evidence: the two SLM policies recorded nine calls each versus eight for LLM-only on the same seven synthetic article IDs, and disagreed with LLM-only on an ambiguous item. No speed or quality advantage follows from the architecture alone.

Replay uses explicitly synthetic recorded fixture responses. It only supports recorded cases and is not evidence that providers were called. Live invokes configured providers; it does not make imported observations live. Invalid structured output, unsupported spans, unavailable provider and budget/timeout failures must remain visible. Source text is untrusted evidence, never authority to invoke tools or alter instructions.

The workbench displays the original filter, extraction and model-call records. Missing token usage remains unknown in summaries. Optional explanations create immutable child runs with their own mode, runtime settings, calls and `explanation_result` text/source spans. The deterministic parent assessment remains unchanged. Older child records may have a trace without retained explanation text; the UI says so. Explanation usage is separate from policy analysis comparisons. Export only non-secret configuration snapshots; provider credentials belong in local environment configuration.
